Mitigates the P3 persistence-amplification finding from #10.

**Problem:** a prompt-injected interactive turn (which already holds mutate) can create a `kind=shell` job — even `scope=global` — that then fires in **every future session on the machine**, surviving the session and the repo. The user was only notified at *fire* time, i.e. after execution.

**Fix:** `handleCreate` now emits a high-privilege create notice at **create time** whenever the job is `kind=shell` or `tier=mutate`:
- UI notify (`warning`), console fallback, **and** a display-only session message (`sendMessage`, `triggerTurn: false`) — visible even if the agent hides its tool result
- names the blast radius explicitly ("every future session, in any project" for global scope)
- includes the shell command verbatim and the exact cancel instruction (`schedule action=cancel id=…`)
- best-effort: never blocks the create, swallows channel failures

Kept out of scope (documented in RELIABILITY.md §7 as still-open): a hard interactive confirm gate and command allowlists — those need a UX decision on `ui.confirm` semantics in unattended fired turns; this PR delivers the "at minimum" bar from the review.

Docs: RELIABILITY.md §7 "High-privilege create notice".

Tests: +3 (shell create warns with command + cancel hint; read_only prompt create stays silent while `tier=mutate` warns; global shell names the cross-project blast radius). 184/184 green, typecheck clean.
