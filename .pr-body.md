Resolves the closed-world-blocklist P2 finding from #10.

**Problem:** `MUTATE_TOOLS = {edit, write, bash}` is a closed-world blocklist. Under `read_only`, a malicious fired prompt simply calls `terminal_exec` (arbitrary commands via a terminal extension), a write-capable MCP tool, or `agent_send` to drive peer agents that hold mutate privilege. The tier label promised more than the mechanism enforced.

**Fix:**
- **`read_only` → strict allowlist (new default).** Known read tools allowed (`read`, `grep`, `glob`, `web_search`/`web_read`, `auggie_codebase-retrieval`, `list_peers`, `show_*`, `terminal_read/list/wait`); everything else — including **unknown tool names** — fails closed with `terminate: true` and a reason pointing at the escape hatch. `mcp` is deliberately excluded: the gateway executes arbitrary registered MCP tools, so a name-level allow cannot separate reads from writes.
- **`suggest`** stays blocklist-based by design (edit/write are needed for drafting) but now blocks the obvious arbitrary-exec surfaces (`terminal_exec/write/write_file/run/start`) and peer messaging.
- **Peer messaging (`agent_send`/`agent_request`) blocked** under both `read_only` and `suggest`, in both modes — an injected scheduled turn must not steer other agents.
- Case-insensitive tool-name matching (`Bash`, `EDIT` blocked too).
- **Escape hatch:** `PI_SCHEDULE_PRIVILEGE_MODE=legacy` restores the old core blocklist for `read_only` (peer messaging still blocked), for setups whose scheduled tasks need non-core read tools.

**Behavior change:** `read_only` scheduled jobs using non-allowlisted read tools will now be blocked with a clear reason — that is the point (fail closed); switch those jobs to allowlisted tools, `tier=suggest`, or set the env var.
